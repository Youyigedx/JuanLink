## 四、必须处理的问题（按优先级）

### 🔴 P0-1　vendored 的 DrawBox 是他人代码，不能计入你的独创部分

`composeUi/src/commonMain/kotlin/io/ak1/drawbox/` 是 **18 个文件、6,044 行**的上游代码

**为什么是问题**：软著保护的是"你独立创作的表达"。把他人代码整段放进提交源程序，
一是审查中若被识别，会牵连独创性判定；二是即使通过，你实际获得的保护并不覆盖这部分。

**处理方式（推荐 A）**：
- **方案 A（推荐）**：提交源程序时**只提交自有代码**，即排除 `io/ak1/drawbox/` 整个目录。
  你的自有代码 8,352 行仍远超体量要求，完全不必靠他人代码凑数。
  同时在申请材料"说明"里或单独附件写明：本软件使用了 Apache-2.0 许可的开源绘图引擎 DrawBox，
  其代码不计入本次登记范围。
- **方案 B**：若因打包完整性必须包含，则在源程序相应页面**逐页标注**该部分为第三方开源代码并注明许可，
  并在申请表中如实说明。
- **绝对不要**：把 `io/ak1/drawbox/` 当成自己的代码静默提交。

> ### 🚨 关键冲突警示（务必先读，容易做错且后果不可逆）
>
> 为了"规避软著补正"而**删掉 `io/ak1/drawbox/` 里的 `LICENSE`、版权声明或 `NOTICE.txt`**，

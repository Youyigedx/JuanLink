## 四、已知构建问题与处理

### 4.1 release 构建：R8 报 `Missing class java.net.http.HttpClient`

**现象**：`:androidApp:assembleRelease` 在 `minifyReleaseWithR8` 失败：

```
ERROR: R8: Missing class java.net.http.HttpClient
       (referenced from: ... DefaultRendezvousClient.<clinit>())
```

**原因**：会合客户端用 JDK 内置的 `java.net.http.HttpClient`，而
**Android 的 `android.jar` 里没有 `java.net.http.*`** —— 该类自 Android 13（API 33）
起在**设备运行时**提供，但未纳入编译用 SDK，故 R8 全量压缩时判定为缺失类。

**处理**：在 `androidApp/proguard-rules.pro` 增加 `-dontwarn java.net.http.*`
（规则取自 AGP 自动生成的 `build/outputs/mapping/release/missing_rules.txt`）。
因 `minSdk = 33`，运行时必然存在该类，抑制编译期告警是安全的。

> 这与桌面端不同：桌面端由 jpackage 打包最小运行时，需在
> `desktop/build.gradle.kts` 显式声明 `modules += listOf("java.net.http")`。
> **两处都要改，只改一处会在另一平台失败** —— 这一点已经在两个平台上各自实测确认。

### 4.2 离线构建缺依赖

`:androidApp:assembleRelease` 在 `--offline` 下会因缺
`org.jetbrains.compose.ui:ui-backhandler-android:1.9.1` 失败。
该构件在 Maven Central（`repo.maven.apache.org`），可正常下载。
Debug 构建不受影响。

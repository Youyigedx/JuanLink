# 交存文档说明（软著登记用）

> 生成工具：`tools/make_doc_submission.py`
> 生成产物：`out/交存文档-软件说明书.html`（打印用）、`out/交存文档-软件说明书.txt`（核对用）
> 本文件是**给申请人看的操作与合规说明**，不是交给版权中心的材料本身。
>
> 源程序部分的对应说明见 [交存源程序说明.md](交存源程序说明.md)。

## 一、官方规格依据

来源：中国版权保护中心官网（完整调研与取证边界见
[软著申请可行性审计.md](软著申请可行性审计.md) 第七节）。

| 项 | 官方要求 | 本次是否满足 |
|---|---|---|
| 页数 | 前 30 页 + 后 30 页，各连续 30 页 | ✅ 共 **56 页，不足 60 → 全部提交** |
| 行数 | 文档**每页 ≥30 行** | ✅ 每页**恰好 30 行**（已逐页校验，0 页不足） |
| 页眉 | 标「软件名称 + 版本号」，且**须与申请表一致** | ✅ `Juan LinK V1.0` |
| 页码 | **自目录起**编号 | ✅ 全文连续页码，目录在封面之后 |
| 格式 | PDF、纵向 | ✅ 浏览器打印为 A4 纵向 PDF |
| 配图 | — | ✅ 内嵌 **4 张界面截图**（见下文） |

> ⚠️ **文档是「每页 ≥30 行」，源程序是「每页 ≥50 行」——两者不同，别套用。**

### 为什么是 56 页

素材共 7 份。官方规则是「不足 60 页全部提交」，
56 页即全部提交，**不需要也不应为了凑到 60 页而填充无关内容**。
封面、目录、各章末页、插图页均已补足到 30 行，避免出现「不满 30 行」的瑕疵页。

## 二、生成与打印（三步）

### 1. 生成

```bash
python3 tools/make_doc_submission.py "<仓库路径>" --name "Juan LinK" --version "V1.0"
```

**软件名称与版本号必须与申请表逐字一致**，否则页眉不符会被要求补正。

### 2. 打印为 PDF

浏览器打开 `out/交存文档-软件说明书.html` → `Ctrl+P`：
- 目标：**另存为 PDF**
- 布局：**纵向**
- 页边距：默认

文件内已内置 `@page A4 portrait` 与分页规则（每页 30 行、页眉固定、页码在右上角）。
顶部黄色「打印说明」条**不会打印**。

### 3. 核对

`out/交存文档-软件说明书.txt` 是同一内容的纯文本版，用于快速核对页数、页眉与目录页码。

> 目录页码由生成器按**实际分页**计算（两遍法：先渲染算真实页号，再生成目录），
> 已逐条校验与正文一致。

### 界面截图（4 张）

| 图 | 内容 | 来源 |
|---|---|---|
| 连接面板 | 配对码 / 扫码 / 连接串三种加入方式 | `assets/screenshots/02-连接面板.png` |
| 主界面 | 顶部栏、工具栏、样式栏、画布与缩放控件 | `assets/screenshots/01-主界面-画布与工具栏.png` |
| 历史快照 | 手动/定时快照侧栏 | `assets/screenshots/04-历史快照面板.png` |
| 设置面板 | TURN 中继与会合服务配置 | `assets/screenshots/03-设置面板.png` |

**截图怎么来的**：`desktop/src/jvmTest/.../DocScreenshotTest.kt` 用
`androidx.compose.ui.ImageComposeScene`（Compose Desktop 的离屏渲染入口）
把**真实 `AppRoot` 与 `AppState`** 渲染成 PNG；画布内容通过
`Intent.AddElement` 注入真实元素，与用户实际绘制走同一条路径。

- 不用屏幕截图：依赖窗口位置/前台状态/屏幕是否锁定，结果不确定
- 不用 `captureToImage`：那是 Android 的 API，Compose Desktop **没有**

重新生成截图：

```bash
./gradlew :desktop:jvmTest --tests '*DocScreenshotTest*'
```

> 生成器会把插图复制到 `out/figs/` 并用相对路径引用，
> **提交时整个 `out/` 目录一起打包即可**，不必依赖仓库其他位置。

### 排版处理说明

- 按 **Markdown 语义**渲染（标题、列表、表格、代码块），不是逐行原样输出
- 表格按**显示宽度**对齐（CJK 字符按 2 宽计算），超宽单元格折行并缩进续行
- 中文按显示宽度折行，避免右侧参差
- 插图从 `<pre>` 中跳出，以真实 `<img>` 渲染（`<pre>` 内放 `<img>` 不会显示为图）
- Markdown 里的图片相对路径按**该 md 文件所在目录**解析（不是仓库根）
- **丢弃打印噪声**：`<div>`/`<img>` 等 HTML 片段、**远程**徽章图片（本地图片保留为插图）
- 纯文本版无法显示图片，以 `[插图：文件名]` 占位，避免读者以为漏内容

## 五、重新生成

素材或代码变更后重新生成即可（幂等，会覆盖 `out/` 下同名文件）：

```bash
# 默认：Juan LinK V1.0，每页 30 行
python3 tools/make_doc_submission.py "<仓库路径>"

# 自定义名称/版本（须与申请表一致）
python3 tools/make_doc_submission.py "<仓库路径>" --name "申请表的名称" --version "V1.0"
```

> 如需增删章节，编辑 `tools/make_doc_submission.py` 顶部的 `SECTIONS` 列表。
